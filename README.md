# Project 100

설치 없이 GitHub Pages에서 동작하는 12주 운동 기록 PWA입니다.

- **오늘:** 운동 시작, 한 종목씩 완료·건너뛰기, 일시정지, 이어하기, 종료 요약
- **계획:** 시작일 기준 12주 일정을 실제 날짜와 요일로 표시하는 미리보기
- **기록:** 실제 운동 이력, 체중·허리둘레·수면 기록, 날짜 간격을 반영한 체중 그래프
- **설정:** 시작일·목표 체중, 설치, JSON 백업·복원

## 개발

빌드나 외부 런타임 의존성 없이 ES modules를 사용합니다.

```sh
python -m http.server 8765
npm test
```

`http://localhost:8765`에서 실행합니다. `npm test`는 Node.js 내장 테스트 러너를 사용합니다.

## 구조

- `data/`: 기존 12주 운동 구성, 고정 종목 ID, 초기 중량, 자세 안내
- `domain/`: 날짜 계산과 운동 상태 전환
- `store/`: 저장·검증·이전 기록 변환
- `views/`: 오늘·계획·기록·설정 화면
- `styles/`: 밝은 테마와 반응형 화면
- `app.js`: 이벤트 연결, 입력 초안 보존, 화면 이동
- `sw.js`: 전체 앱 파일의 오프라인 캐시 및 업데이트

## 기록 보존

`project100-v2`는 원본으로 유지하며, 검증된 새 기록을 `project100-v3`에 저장합니다. 기존 체크는 당시 시작일과 주차·일차를 기준으로 날짜를 부여합니다. 체중, 중량, 일별 기록 및 변환 전 원문도 보존합니다. 시작일을 바꿔도 이미 저장한 운동 날짜와 종목 구성은 바뀌지 않습니다.

추천 중량은 종목 완료 시 사용자가 확정해야 실제 기록이 됩니다. 입력 중인 값은 초안으로 보존합니다. 앱을 떠나면 타이머를 일시정지하고, 다시 열면 명시적으로 이어서 진행합니다. 중간 종료는 실제 완료·건너뜀·미완료를 구분합니다.

잘못된 백업은 기존 기록을 바꾸지 않습니다. 다른 탭의 변경이나 저장 공간 부족이 발생하면 실패를 알립니다. 자동 클라우드 동기화는 없으며 기기 이동에는 JSON 백업을 사용합니다.

## 배포

`main`의 기존 GitHub Pages workflow로 배포합니다. 앱 파일을 바꿀 때 `sw.js`의 `CACHE` 버전도 올려야 합니다. 새 버전은 업데이트 안내에서 적용하며, v2 앱에서 최초 업그레이드할 때는 기존 캐시를 교체합니다.
